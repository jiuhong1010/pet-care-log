# 毛毛档案：手机优先差异化改版设计简报

## 1. Feature Summary

本次改版把毛毛档案从“宠物记录工具”升级为“家庭与医生之间的健康交接本”。主要用户是在家中、通勤途中或宠物医院里单手操作手机的宠物主人；产品需要让他们快速看懂今天最重要的事情，并把一次异常逐步整理成可以直接用于看诊的资料。

差异化核心不是增加更多记录分类，而是把用户的担心和零散观察转换成一个逐渐准备完整的“看诊包”：症状、时间、照片、体重变化、当前用药和想问医生的问题都围绕同一次健康事件组织。

## 2. Primary User Action

首页最重要的动作是“记下刚刚的变化”。用户不需要先判断属于哪种表单，只需开始一次健康事件，选择或描述刚发生的变化；系统随后把信息放入照护轨迹和看诊包，并在合适的时候引导补充证据。

正常状态下，用户首先理解“今天是否有需要处理的事情”；异常状态下，用户首先理解“这次不舒服已经持续多久、目前收集了什么、下一步应该补充什么”。

## 3. Design Direction

### Visual lane

采用第二轮视觉探针第 3 张作为主方向：成熟线稿卡通、大留白、非对称构图、流动照护轨迹与少量清新纯色。保留第 1 张“看诊包”作为物件隐喻，但不使用绘本式满屏插画；不采用第 2 张的 3D 玩偶语言。

### Color strategy

产品主体采用 **Restrained** 策略；宠物身份区和照护轨迹允许局部 **Committed**：

- 云白：主要背景，保持真正中性，不使用奶油或米黄底。
- 午夜青：正文、关键时间与高可信信息。
- 海玻璃绿：看诊包、已收集观察与安心状态。
- 淡青蓝：轨迹、辅助区域与当前宠物的柔和背景形状。
- 日光黄：只用于“下一件要做的事”和当前轨迹节点。
- 珊瑚橙：来自宠物角色，只用于身份与少量人情味细节。
- 警示红：仅用于逾期和真正需要立即关注的状态。

所有颜色均以 OKLCH 建立明暗阶和深色模式映射；按钮不使用渐变，状态不只依赖颜色表达。

### Theme scene

用户傍晚在家中发现宠物和平时有一点不同，用一只手打开手机，在自然室内光下迅速记下一条变化；界面让人镇定、清楚，并感到这些观察正在被妥善收好。

### Anchors

- 视觉探针第 3 张：线稿宠物、流动轨迹、清新色彩与留白。
- Apple Health：健康事实、时间和状态的可信层级。
- Day One：个人档案的温度、时间线叙事和长期使用感。

## 4. Scope

- **Fidelity**：production-ready。
- **Breadth**：首次访问品牌首页、宠物档案首页、一次健康事件、看诊包、用药接力，以及现有记录入口的统一改造。
- **Interactivity**：最终交付为可点击、可编辑、可部署的真实 React 界面，不以生成效果图代替产品。
- **Time intent**：分阶段完成，但每个阶段达到可上线标准，不交付半成品原型。
- **Execution**：单代理实现；正式编码阶段使用高推理强度。

### 第一阶段上线边界

1. 重做手机优先首页与桌面响应式结构。
2. 新增“这次不舒服”健康事件与观察时间线。
3. 自动汇总可打印的看诊卡 / 看诊包。
4. 为用药记录补充完成状态、时间和照护人名称。
5. 保留并迁移现有宠物、疫苗驱虫、体重、用药与就诊数据。

### 暂不纳入第一阶段

- AI 症状诊断与疾病概率判断。
- 云端账号、实时家庭同步和医院系统对接。
- 社区、电商、保险推荐与泛内容资讯。
- 需要上传隐私材料到第三方的自动 OCR；未来只能作为明确选择加入的能力。

## 5. Layout Strategy

### 首次访问 / 品牌首页

- 首屏只表达一个承诺：把每一次异常和照顾整理成看诊时说得清的时间线。
- 使用一个原创线稿宠物与看诊包组合插画，不用功能卡片网格。
- 显示一段真实的三步照护轨迹作为产品证明，而不是罗列十项功能。
- 主按钮为“建立第一份档案”；隐私承诺紧邻按钮。

### 手机档案首页（360–430px）

1. **紧凑顶部栏**：产品名、宠物切换、设置；不显示搜索和无意义通知铃铛。
2. **宠物身份场景**：当前宠物线稿角色、姓名和一句自然语言状态。高度不超过首屏的 32%。
3. **照护轨迹**：从最近一次观察流向下一件要做的事。正常时保持稀疏；有异常时显示持续时间和最新变化。
4. **看诊包抽屉**：显示已收集的资料类型和缺失项；没有健康事件时保持收起，不制造焦虑。
5. **单一主动作**：底部安全区上方的“记下刚刚的变化”。次要新增功能进入一个明确的记录菜单。
6. **历史内容**：体重、疫苗、用药和就诊按时间线或分组列表继续向下，不在首屏堆四个等权入口。

手机端不得出现横向页面滚动；所有主要触控区域至少 44×44px；粘性按钮避开系统安全区和软键盘。

### 平板与桌面（768px 以上）

- 768–1023px 保持单列主流程，内容最大宽度约 720px。
- 1024px 以上使用结构性双栏：左侧约 320px 的宠物身份、下一件事和看诊包摘要保持可见；右侧承载照护轨迹、趋势和完整历史。
- 不拉伸手机卡片，不把底部导航直接搬到桌面；桌面使用顶部导航和就地详情区域。
- 宽屏内容最大宽度控制在约 1120px，阅读信息不横跨整个屏幕。

## 6. Key States

### 首次使用

用户看到品牌承诺、一个明确动作和本地隐私说明；添加宠物后直接进入档案，不展示空仪表盘。

### 正常状态

宠物角色保持安静姿态，状态文案为“今天暂时没有需要处理的事”；轨迹只突出下一次疫苗、驱虫、复诊或用药。

### 临近到期

日光黄节点配合明确日期和剩余时间；主角仍是任务内容，不把整页染成警告色。

### 已逾期

红色只出现在任务节点、状态词和图标；同时说明逾期天数与可采取动作。

### 活跃健康事件

首页切换为事件上下文：事件名称、开始时间、持续时长、最新观察和“记下变化”。看诊包显示已收集与建议补充项。

### 症状已缓解

用户可结束事件并写一句结果；事件保留在档案时间线中，不继续提示看诊。

### 准备看诊

看诊包生成一页摘要：宠物信息、异常时间线、体重变化、当前用药、相关照片、既往过敏 / 病史、希望询问的问题。提供打印和浏览器 PDF 导出。

### 看诊后

用户补记诊断、医生医嘱、药物与复诊日期；这些信息可一键进入现有用药和到期提醒，不重复填写。

### 空记录

空状态说明记录的实际价值并给出一个动作，例如“记下第一次体重，之后才能看见变化”；不使用泛化的“暂无数据”。

### 存储失败与附件容量不足

明确说明哪些内容尚未保存，保留用户输入，并提供重试、减少附件或导出已有数据的路径。

### 深色模式与减少动态

深色模式保持相同信息顺序和色彩角色；插画更换为深色适配版本。减少动态模式禁用轨迹生长动画，仅保留即时状态切换。

## 7. Interaction Model

### 记录一次变化

1. 点击“记下刚刚的变化”。
2. 进入全屏手机流程 / 桌面就地侧栏，而不是小型居中模态框。
3. 先选择变化类型：食欲、精神、呕吐、排便、排尿、呼吸、疼痛或自定义。
4. 选择程度与发生时间；备注和照片均为可选项。
5. 保存后立即回到轨迹，新节点短暂强调，并提示它已经进入看诊包。

### 建立或继续健康事件

- 第一次异常自动创建事件，用户可修改名称。
- 短时间内的后续观察默认归入同一事件，避免每次重复分类。
- 用户始终可以开始新事件或把记录移动到其他事件。

### 看诊包

- 默认折叠，只显示资料完整情况，不使用虚假百分比健康分数。
- 展开后按“发生了什么、现在怎样、正在使用什么、想问什么”组织。
- 所有自动汇总都能回到原始记录；用户可排除不想分享的内容。

### 用药接力

- 用药任务显示药名、剂量、计划时间、上次完成时间和记录人。
- 完成操作需要一次明确确认，并允许在短时间内撤销。
- 第一阶段只记录当前设备上的照护人名称，不承诺实时家庭同步。

### Motion

- 常规状态变化 160–220ms，使用 ease-out-quart / quint。
- 轨迹新增节点只做短距离展开与颜色过渡，不使用弹跳。
- 宠物切换采用交叉淡入；任何内容默认先可见，动画不控制可用性。

## 8. Content Requirements

### 核心文案

- 品牌承诺：把每一次变化，整理成看诊时说得清的时间线。
- 正常状态：小满今天很安心。
- 异常入口：记下刚刚的变化。
- 看诊包说明：观察随时记，看诊时不遗漏。
- 事件结束：这次不舒服后来怎么样了？
- 空时间线：从第一条真实观察开始，不需要每天打卡。

### 动态数据范围

- 宠物：常见 1–3 只，支持至少 20 只而不破坏切换器。
- 单次健康事件：典型 2–8 条观察，最大按数百条可滚动处理。
- 照片：单条观察 0–4 张；缩略图延迟加载并限制本地容量。
- 历史记录：按年增长；列表需要增量渲染或按时间分段，不能一次铺满首页。
- 文本：中文为主，姓名、药名和医院名允许较长字符串并正确换行。

### Asset roles

- **生成式图片资产**：统一风格的十种宠物线稿角色、看诊包物件、首次使用组合插画。输出需要透明背景，不包含文字、按钮、状态栏或 UI 图标。
- **代码 UI**：所有文字、按钮、表单、轨迹节点、图表、提醒、导航与状态。
- **图标系统**：继续由 `UiIcon` 统一使用 Phosphor regular，不在生成图片中绘制操作图标。
- **用户内容**：宠物照片、症状照片、处方与检查资料；第一阶段保存在本地 IndexedDB，导出时由用户选择是否包含。

## 9. Recommended Implementation References

正式实现前依次读取并应用：

1. `layout.md`：手机到桌面的结构性重排与留白节奏。
2. `colorize.md`：建立清新全色角色但保持产品可读性。
3. `typeset.md`：控制产品名、宠物身份、时间和医疗事实的层级。
4. `delight.md`：把卡通角色和看诊包变成有意义的情绪细节。
5. `animate.md`：照护轨迹与记录反馈的克制动效。
6. `adapt.md`：360px 手机、平板、桌面和大字号适配。
7. `harden.md`：本地容量、导入迁移、失败恢复和长文本边界。

## 10. Open Questions

无阻塞性的视觉问题。默认按以下决策进入实现：

- 手机端优先，浅色为主并同步完成深色模式。
- 视觉采用探针第 3 张，清新纯色，不使用渐变按钮。
- 第一阶段保持本地优先；附件使用 IndexedDB，现有结构化数据继续兼容。
- 看诊卡先采用可打印网页与浏览器 PDF，不引入服务器。
- AI / OCR、真实多人同步和医院对接推迟到后续独立决策。
